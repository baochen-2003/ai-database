OceanBase AI 数据库面向 AI 应用与 Agent 的多模数据库

OceanBase AI 数据库在一个引擎中提供标量、JSON、全文、向量与多模态数据的存储与检索，支持库内 AI 推理、Agent 记忆管理与数据分支，替代 MySQL、搜索引擎、向量库与数据湖的多系统组合。

架构对比

告别多系统拼凑，一库跑通 AI 全链路

传统做法：多系统拼接

传统架构需组合 MySQL、Elasticsearch、向量库及对象存储等多个独立系统，分别处理结构化数据、关键词搜索、语义检索与文件存储。这种分散模式导致应用层胶水代码，多系统同步，多套权限，多份数据，运维成本高昂。

OceanBase AI 数据库：一个原生引擎

OceanBase AI 数据库以“一份数据、一套事务、一条 SQL”为核心，在单一引擎内集成混合搜索、库内推理、Agent 原生及 LOB 分层能力。它消除了跨系统集成痛点，大幅简化架构并提升数据一致性与开发效率。

核心能力

AI 能力内生，不靠外挂拼装

混合搜索、AI 算子、Agent 数据管理由内核直接提供，共享同一份数据、同一套事务和同一套权限。

核心能力

一条 SQL，五类检索组合

标量、JSON、全文、向量、空间检索在同一条 SQL 中执行，优化器统一选择计划，融合排序在库内完成——无需在应用层归并多套系统的返回结果。

  • 五类检索在同一条 SQL 中组合

    Btree、多值索引、倒排 BM25、HNSW / IVF、GIS 索引，每种数据类型有匹配的加速路径。

  • 库内融合排序

    内置 RRF、WEIGHT_SUM、MINMAX 归一化，多路召回直接返回排好序的 Top-K。

  • 写入即可见

    事务提交后各类索引立即生效，无需等 CDC 同步到外部搜索服务或向量库。

从只存不算，到即存即算

模型注册为数据库对象，SQL 中直接调用切分、向量化算子，推理结果写回原表并自动建立索引——不必在应用层维护模型调用、结果回写和索引同步。

  • Model in DB

    DBMS_AI_SERVICE 注册嵌入式、生成式、多模态、重排序模型。模型作为数据库对象，纳入版本管理、权限控制、血缘追踪与审计。

  • AI 算子

    摘要 → 切分 → 向量化在 SQL 内完成，结果入表后自动创建全文与向量索引，像普通列一样被查询、索引和 Join。支持 Python UDF 扩展。

  • 多模表

    文档、图片、音视频作为 LOB 入表，按大小与访问模式自动路由到 InRow / OutRow / 对象存储，对应用透明。文件与业务字段同一事务提交或回滚、共享一致快照、统一权限。

rag_pipeline.sql
-- 模型成为数据库对象
CREATE MODEL my_embedding_model
  TYPE 'embedding'
  PROVIDER 'openai';

-- 文档入库，同时完成向量化
INSERT INTO knowledge_base
VALUES (title, content,
  AI_EMBED(content USING my_model));

-- 搜索、重排、答案生成，一条 SQL
SELECT AI_COMPLETE(
  AI_RERANK(hybrid_results)

能隔离、有记忆、会试错

千万级 Agent 实例共享一套物理表，记忆用一条 SQL 召回，对比实验在 Fork 出的数据分支上运行——不必为每个 Agent 建表，也不必复制整库来做实验。

  • 五层隔离

    租户级（独立资源配额与权限边界）、Database 级、Namespace 级逻辑表、表级、行 / 列级 RLS。同一套物理表支撑千万级实例，元数据不随实例数膨胀。

  • 记忆召回

    长期记忆（向量 · 文本 · JSON）、短期状态、工具调用记录、多模态输入统一存储，标量过滤 + 全文 + 向量 + JSON 过滤在一条 SQL 内完成。

  • Fork Database

    Copy-on-Write 共享基线、只存增量，毫秒级创建数据分支，支持 MERGE 与 DROP。分支间增量变更互不影响，实验结果可跨分支查询对比。

  • 冷热分层

    沉睡实例数据自动沉降到对象存储，被唤醒时从共享存储加载，RPO=0。

文档入库，答案出库

文档解析、切分、向量化、混合搜索、重排和生成在同一个数据库内完成，不必再串联文档存储、Embedding 服务、向量库、搜索引擎和编排框架。

  • 替代文档存储、Embedding、向量库、搜索引擎、编排框架等组件
  • 全文与向量索引实时一致，权限与审计贯穿全链路
  • AI 算子可经 Python UDF 扩展

记得住，敢试错

短期状态、语义记忆和业务事实存在同一份数据里，共享同一套事务；需要做对比实验时 Fork 出数据分支，失败即丢弃——不再需要 Redis、向量库和 MySQL 各存一部分上下文。

  • 长期记忆、短期状态、工具调用记录、多模态输入统一存储与召回
  • Namespace 级逻辑表支撑千万级 Agent 隔离
  • Fork Database 毫秒级实验沙箱，MERGE / DROP 收敛，Bad Case 可回溯到 Prompt、模型与工具链
  • 沉睡记忆自动沉降到对象存储，RPO=0

文件也是数据

文件、模型推理结果和业务字段进入同一张表后，可以按业务属性、摘要关键词和画面语义组合查询——例如在一批车载视频里检索“雨天某车辆在某路段的分流口画面”，是一次普通 SQL 查询。

  • 业务属性、摘要关键词、画面语义组合成一次查询
  • 推理结果回写原表，像普通列一样被查询、索引和 Join
  • LOB 三形态自动分层存储（敬请期待）

省掉一条双链路

高频实时写入与大批量导入进入同一个引擎，物化视图增量刷新支撑准实时查询，不必再维护 Lambda 架构的两条链路。

  • 流批一体写入，Direct Load 高速导入，物化视图 + MLog 增量加工
  • 行存、列存、行列混存按需定义，向量化执行较非向量化大幅提升
  • 原生 MPP，节点 - 分区 - 任务多层并行
  • 兼容 Arrow Flight SQL，原生集成 Spark / Daft / Ray
  • Iceberg / Hive / Paimon 湖上查询加速，统一元数据。
